# v0.2 design: hide more, peek with friction, popup redesign

Status: approved in conversation 2026-09-29, pending written-spec review.
Note: the peek rules here (lasts until leaving Home, reason in tab memory) are superseded by `2026-10-01-timed-peek-design.md`.

## Goal

Make YouTube calmer beyond the home feed and Shorts, and replace "the feed is
simply gone" with "the feed is there if you really want it, at a cost you
choose". Everything in v0.2 runs in the browser and makes no network requests,
so the privacy policy does not change.

Out of scope for v0.2: honest titles (v0.3), onboarding flow, any backend.

## Settings

All settings stay in `chrome.storage.sync` under the `settings` key. The shape
stays flat, like v0.1. New keys get defaults through `mergeWithDefaults`, so a
v0.1 install upgrades without losing anything.

```js
{
  shortsBlocking: true,        // existing
  hideHomeFeed:   true,        // new. false = real home feed, no panel
  hideUpNext:     true,        // new
  blockAutoplay:  true,        // new
  hideComments:   false,       // new
  peekLevel: "reason",         // new. "pause" | "reason" | "none"
  feedMode: "widgets",         // existing. what the panel shows
  aiInstruction: "",           // existing
  widgets: { todo, timer, quote } // existing
}
```

`YFB.PEEK_LEVELS` is added to `defaults.js` next to `FEED_MODES`.

Defaults live in one place. `defaults.js` switches from `window.YFB` to
`globalThis.YFB` so the service worker can load it with `importScripts`, and
`background.js` drops its duplicated copy of the defaults.

## Page behavior

### Home feed and peeking (`feed-replacer.js`)

- `hideHomeFeed: false` unmounts the panel and shows the real feed.
- When the feed is hidden, the panel shows its current mode (blank, widgets,
  AI preview) plus, unless `peekLevel` is `"none"`, a "Show my feed anyway"
  link below it.
- `"pause"`: the link starts a 10 second countdown shown in the panel. The
  countdown only advances while the tab is visible (`visibilitychange`). A
  "Never mind" link cancels it.
- `"reason"`: the link first shows a one-line input, "What did you come for?",
  that needs at least 3 non-space characters. Submitting starts the same
  countdown.
- When the countdown ends, the panel is removed and the real feed shows.
- The peek lasts until the user leaves the home page. The "peeked" flag is
  in-memory in the content script and is cleared by `sync()` on any navigation
  away from home, so coming back to Home shows the panel again.
- `"none"`: no link. Search and Subscriptions still work.

### "You came for" banner (new `reason-banner.js`)

- After a `"reason"` peek, the reason is kept in the content script's memory
  for that tab. Not `sessionStorage`: YouTube's own scripts can read page
  storage, and the reason is the user's private note. Memory survives YouTube's
  client-side navigation; a full page reload clears it. The banner and the
  peek input live in YouTube's page, so YouTube's scripts can still see the
  reason on screen and as it is typed; the goal is that the extension never
  persists or transmits it.
- On every YouTube page in that tab, a slim banner at the top reads
  "You came for: <reason>" with a close button. Closing it removes the key.
- The reason is inserted with `textContent`, never as HTML.

### Watch page (new `watch-page.js` + `watch-page.css`)

Each setting toggles a class on `<html>`, and the CSS hides by class, the same
reversible pattern as `hide-shorts.css`. Changes apply live with no reload.

| Setting | Class | Hides |
|---|---|---|
| `hideUpNext` | `yfb-hide-upnext` | `#secondary #related`, end-screen video wall (`.ytp-endscreen-content`), end-screen cards (`.ytp-ce-element`), the autoplay "Up next" overlay (`.ytp-autonav-endscreen-countdown-overlay`) |
| `hideComments` | `yfb-hide-comments` | `ytd-comments#comments` |
| `blockAutoplay` | `yfb-block-autoplay` | the autoplay countdown overlay, as a backstop |

- The playlist panel (`ytd-playlist-panel-renderer`) inside `#secondary` stays
  visible so playlists still work.
- `blockAutoplay` also switches YouTube's own autoplay toggle off: on each
  `yt-navigate-finish` to `/watch`, if `.ytp-autonav-toggle-button` has
  `aria-checked="true"`, the script clicks it once. It retries briefly while
  the player loads.
- Turning `blockAutoplay` off does not turn YouTube's autoplay back on. From
  then on that toggle belongs to the user.
- YouTube selectors change. All selectors sit in one constant block at the top
  of each file so they are quick to update.

## Popup redesign

Layout, top to bottom:

1. **What should we hide?** One card, five toggles, copy from the mockups:
   - Home feed: "The endless grid on the front page"
   - Shorts: "Vertical videos, wherever they appear"
   - Up next: "Suggestions beside and after a video"
   - Autoplay: "The next video starting on its own"
   - Comments: "Below every video"
2. **How hard should it be to peek?** Three option cards:
   - Pause: "Wait 10 seconds before the feed opens"
   - Pause and say why: "Type what you came for, then wait"
   - No peeking: "The feed stays hidden. Search and subscriptions still work"
3. **Instead of the feed.** Blank / Focus widgets / AI-curated (marked as a
   preview), with the widget checkboxes under Focus widgets and the AI
   instruction box under AI-curated.

Sections 2 and 3 are hidden while the home feed toggle is off.

Footer: version number only (drops "Sideload build, not on the Web Store").

### Visual

- Follows the system theme. Dark is the mockup: near-black background, slightly
  lighter cards, white titles, grey sub-lines, red toggles and red outline on
  the selected option. Light is the same structure on white and light grey
  cards with the same red.
- Colors are CSS custom properties on `:root`, redefined under
  `prefers-color-scheme: dark`.
- System font stack. Buttons have gently rounded corners, not pill shaped.
- The on-page peek link, countdown, reason input and banner reuse the same
  tokens in `overlay.css`.

### Copy and accessibility

- Plain copy, no em dashes, anywhere in the popup or on-page UI. Existing em
  dashes in popup and panel copy are removed.
- Every toggle and option is a real `<input>` (checkbox or radio) with a
  `<label>`, so keyboard and screen readers work, with a visible focus ring.
